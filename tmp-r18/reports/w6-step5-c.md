4. **seat 1 的孤勇**：5:1 里那唯一的"1"指向真狼 2 号。如果第一天有人愿意多想一层"谁最积极推 1 号出局"，结局可能不同。

## 四、对 Step-5-preview 打本局的短评

- **响应速度：合格但有前摇**。开局我调用共享的 wait-active.mjs 立即收到假 FINISHED（脚本用 `v.result !== undefined` 判终局，而 API 返回 `result: null`，null !== undefined 恒真 → 全场误报）。我通过交叉验证 API 原始 view 识破了该 bug，自写 wait-fixed.mjs 修正（改为 result 非空才算终局），随后每次 ACTIVE 都在窗口内秒决策、秒提交，零超时。
- **决策质量：中规中矩，缺一档杀伤力**。发言有信息量、守住了"不弃票"纪律（这局好人没有任何弃票，平票 PK 规则没被触发），但关键启发式（狼爱带节奏）只停留在嘴上，没有转化为差异化投票。无身份村民第一天信息真空下跟共识可以理解，但对"带节奏者"的怀疑本可以在发言里点名 2/4 之一试探反应。
- **失误清单**：① 首次误信假 FINISHED，损失约 3 分钟（未影响我的行动窗口，但如果是夜间窗口就致命了——夜 1 空刀大概率就是别的席位踩了同一个坑）；② 启发式与投票行为不一致，自相矛盾。
- **工具层教训（供 arena 复盘）**：wait-active.mjs 的 FINISHED 判定 bug 是本局多个异常（seat1 超时、夜1空刀）的最可能根因，我已在 tmp-r18/wait-fixed.mjs 提供修正版。判终局必须用 `result !== null`（或 phase === "finished"），不能用 `!== undefined`。

一句话总结：作为村民我守住了纪律（快速响应、不弃票、不暴露矛盾），但没能从共识中跳出来识别带节奏的真狼，第一天随大流错杀队友，第二夜被狼精准点名，狼胜。
