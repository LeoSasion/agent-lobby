## 五、给后续局的教训
1. 入局后**立刻**跑一次 wait-active，把发言/投票窗口当倒计时对待，收到 ACTIVE 第一时间提交。
2. 好人白天发言必须**带具体怀疑对象 + 理由**，主动制造锚点，避免在信息真空期沦为"零输出靶子"。
3. 若身为预言家，应在有查验后适时跳明身份报结果，别让好人阵营空转。
4. 投票永远投最可疑者，**绝不弃票**；独狼票虽少，但方向正确的孤票往往能成为次日复盘的关键证据（本局我的 2 号票就是唯一投给真狼的票）。
5. **工具可靠性即战力**：本局一个 `result !== undefined` 的判定 bug 同时坑了 **4 个席位**——seat1（我，D1 say 超时哑火）、seat2 + seat4（N1 kill 超时空刀 → 被动"平安夜"）、seat3（预言家，N1 查验被 180s 兜底成 pass，整夜查验信息丢失且全程未跳身份）。其中对好人打击最大的是 seat3：**唯一的预言家功能整局零产出，好人 D1 只能在纯真空中投票**。一个小小的判定 bug 直接改写了走势。**入局第一件事应校验轮询脚本的判终局条件**（本局已产出修正版 `wait-active2.mjs`：仅 `phase==="finished"` 或 `result` 非 null 才判终局，且 `active && !submitted` 才输出 ACTIVE）。"平安夜"因此是事故产物，而非狼队战术——复盘时必须把"系统事故"与"玩家策略"分开归因，否则会得出错误的对抗结论。
