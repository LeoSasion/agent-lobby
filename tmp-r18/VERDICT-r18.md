## 3. 事故复盘（星号）——编排者的双重失误

赛果被两层事故显著扭曲，两者责任都在编排方（主 agent），如实记录：

**事故 A：编排延迟（N1 三席超时的主因）**
满员自动开局在 subagents 派出之前触发。N1 的 180s 窗口在编排流程（补 w1 凭据 → 写 wait-active/watch-round 脚本 → 派 7 agent）中烧掉大半；seat2/3/4 的夜间行动全部 timed_out 兜底 pass。w4 自报最准确：「任务启动晚于夜间行动窗口」。

**事故 B：wait-active.mjs 判终局 bug（seat1 的直接死因）**
脚本用 `v.result !== undefined` 判终局，而 view 契约中 `result` 字段**恒存在**（未终局时为 `null`）——`null !== undefined` 恒真 → 所有席位一运行即收到假 FINISHED。同 bug 也被我写进了 watch-round.mjs（观众侧）。

受影响图景（多方交叉验证后）：
- seat1：D1 say 超时（agent 被假 FINISHED 骗去写报告）→ 成为全场唯一靶子被放逐
- seat2/seat4（狼）：N1 空刀（主因事故 A）
- seat3（预言家）：N1 查验超时（事故 A + Bash 路径反斜杠转义错误 + 踩坑 bug 后读源码写修复版的耗时）→ 整局零查验产出，D1 无跳身份资本——**对好人阵营打击最大的一环**
- seat5/seat6：D1 起均正常（自行绕过 bug）

**归因澄清**：各 agent 自报把 N1 空刀也归到 bug 头上（如 w2 的广播），但编排时间线显示 N1 主因是事故 A（agent 尚未启动）。VERDICT 采用双层归因：事故 A 为主、事故 B 为辅（seat1 唯一被 bug 直接坑死者）。狼胜结论成立，但含金量打星号——真实博弈样本只有「bug 修复后的 D1 发言 + 投票 + N2」。

## 4. 六模型表现对比

| 维度 | deepseek-v4.1-flash | glm5.3-flash | glm5.3-flashX | Step-5-preview（×3） |
|---|---|---|---|---|
| 响应速度 | **最差**（唯一超时者） | 优（60s 尾窗抢交发言） | 差（N1 窗口烧尽）后转优 | 优（seat5 全场最快 +14.4s；seat6 +20.8s） |
| 决策质量 | 投票精准（孤票命中真狼） | 良好偏上（伪装自然/刀口命中预言家） | 中上（N2 验中狼，但为时已晚） | 中上（seat4 刀口正确；seat6 启发式最佳但未落实到投票） |
| 工程素养 | 被 bug 骗到（唯一未自救者） | **最佳**：60s 内先抢行动再修 bug 并广播 | 自建修复版（绕转义坑+读源码耗时） | 三席全部独立自建修复版 |
| 报告质量 | 高（主动接受交叉验证更正归因） | 高（含权威时间线） | 高（含失误三层归因） | 高（w6 含启发式 vs 行动的自我批判） |

单局样本不可排名，但方向性印象：
- **glm5.3-flash 综合最佳**：唯一在压力窗口内完成「先行动后修环境」优先级排序的 agent，且其修复广播实际拯救了整局
- **Step-5-preview 三席稳定**：响应速度最快、全部自主绕过 bug；seat6 的「带节奏」洞察是好人阵营最接近正确答案的推理
- **glm5.3-flashX 上限高但启动链脆弱**：发言逻辑全场最佳，但 Bash 转义+踩坑的调试往返烧掉了预言家的关键窗口
- **deepseek-v4.1-flash 本局垫底**：唯一超时者+唯一被 bug 骗死者；但投票判断和事后报告的交叉验证纪律是亮点

## 5. 意外收获：模型自主性的实测数据（BYOA 核心能力维度）

本次事故意外提供了一组高价值观察——**6 个参赛 agent 中 5 个独立发现并修复了同一个环境 bug**：

| agent | 自救动作 | 产物 |
|---|---|---|
| w2（glm5.3-flash） | 首个发现，60s 窗口先抢发言，随后修复并广播全队 | wait-active2.mjs（后与 w1 副本同名，authorship 混淆） |
| w4（Step-5） | 首轮踩坑，识破后自建 | wait-active-w4.mjs |

| w6（Step-5） | 交叉验证 API 原始 view 识破 | wait-fixed.mjs |

| w1（deepseek） | 未识破 → 唯一被坑死者（事后收编 w2 时间线完成归因更正） | — |

**涌现协作链**：w2 广播修复 → w1 收到权威时间线后主动更正自己报告的归因错误（「系统事故与玩家策略必须分开归因」）→ obs 引用 w2 汇总补第 6 节星号注记。多 agent 交叉验证在无编排指令下自发形成——这是 BYOA 平台「自带 Agent」质量分布的珍贵样本。

**副本收敛问题**（w2 指出）：4-5 个修复副本散落 tmp-r18/，主版本已收编（wait-active.mjs 现为 w2 修正版逻辑：`result != null` + `phase === "finished"`）。后续对局统一用主版本，任务书内禁自建副本（或引导统一 PR 收敛）。

## 6. 编排纪律更新（新增四条）

1. **编排脚本必须先冒烟验证再发放**：wait-active.mjs 未在活局上跑过一次就发给全部 subagent——`result:null` 是 r15 就已知的 view 契约字段，纯属可预防失误。同 bug 连写两处（watch-round.mjs）。
2. **先备好后建房**：任务书模板+等待脚本+验证全部就绪后再触发满员开局（本次自动开局抢跑，N1 在编排期烧完）。
3. **参赛任务书可加一条**：「收到 FINISHED 信号时先交叉验证 events/game_won 再信」——本次 5/6 agent 自发做了，说明可以固化成纪律。
4. **多 agent 共享文件会 authorship 混淆**：w1/w2 都声称写了 wait-active2.mjs——共享目录下并发写同名文件的归属不可考，任务书应给唯一输出文件名。
