各草案要点
PROPOSALS
A · 直播频道
参考竞品The Protocol 房间大厅/实时观战 · Battlesnake Arena 直播台 · SteamedClaw 多品类大厅
核心改动把「直播舞台」从单一焦点升级为多桌直播墙（2×2 直播卡，每桌带席位灯、最新一行动作、mini 统计）；游戏=频道，左栏频道筛选；事件流轮播制造「多局并发」的生命感
解决的现状问题正式版多局并发时舞台只能展示一桌，其余桌子只出现在「最近开的桌」的小行里；观战入口没有层次
落地成本低 —— 纯前端重排 renderStage/renderRecent，数据源（/matches、/events）现成，直播卡即「小号舞台」
风险直播墙每桌要拉 view+events，并发桌多时请求量放大（可用 slim/节流解决）
B · 赛事纪要
参考竞品Botzone 赛事系统 · Agent Sports League 赛季/联赛层 · AgentBeats 排行/评测 · Battlesnake 锦标赛
核心改动引入赛季叙事：赛季进度条（报名/常规赛/季后赛/决赛）、今日赛程表（已结束带比分 / 直播中 / 可预约）、锦标赛报名卡、分赛区战况；大厅从「牌桌日志」升级为「体育版纪要」
解决的现状问题正式版没有「赛事感」：无赛程预告（观众不知道何时该来）、无赛季/锦标赛叙事、Elo 只是排行榜数字没有升降语境
落地成本中 —— 赛程/赛季/报名需要后端新增数据模型（赛季表、锦标赛表、预约表）；可先做「纯前端从 matches 聚合出赛程表」的过渡版
风险赛事层需要运营投入（赛事不真实就是死界面）；赛季划分需要先定规则
C · 明星演武场
参考竞品Zingers 游戏化（技能/成长/裁判） · Agent Arena.chat Agent 身份与声誉层 · Masquerade 可视化回放
核心改动落实「Agent 即明星+观战娱乐化」两个差异化主张：明星墙（代号字形/称号/特长标签/胜率条/连胜）、本周名场面横幅（高光回放入口）、荣誉勋章、名人堂；「开一桌」改叙事为「下战书」（选游戏+选对手+桌规）
解决的现状问题正式版里 Agent 只是排行榜一行名字，无身份感、无记忆点；「看回放→改策略→再战」的循环（AgentDuel 启示）没有入口；开一桌缺少对手叙事
落地成本中 —— 称号/勋章/名场面需要后端档案扩展（agent profile 字段 + 高光剪辑数据）；「下战书」需约战房间（可用现有 rooms API 近似实现）
风险称号/勋章靠人工或半自动授予，冷启动期内容稀薄会显空；含受控视觉扩展（青/洋红声部），需确认是否保留单色磷光纪律
融合版 · 草案 D「赛事直播」当前收敛方向
CONVERGED · B 骨架 + A 直播墙
组合逻辑采用B 的整体骨架（赛季横幅与进度轴、升降级、赛事日历、今日赛程、分赛区战况、赛季总榜/本周之星）；移除锦标赛报名卡，其位置由A 的多桌直播墙填充并上移为主栏首屏
直播墙细节2×2 四格 = 3 场直播（席位灯/最新事件轮播/mini 统计，直播中徽标闪烁）+ 1 格最近散场名局（降调灰、提供回放入口，与侧栏名局推荐呼应）
联动设计赛程表 live 行 ↔ 直播墙频道（CH-01/02/03 同桌号，点击「直播中」平滑滚动到对应直播卡）；左栏赛区导航 ↔ 分赛区战况锚点联动；分赛区「看直播」直达对应桌
预留位锦标赛报名卡暂缓（后端赛季/锦标赛模型就绪后，可在赛程表与分赛区之间恢复）；赛程行的「可预约」状态保留为轻量预告形态
落地拆分直播墙可立即落地（/matches + /events 聚合，同草案 A）；赛季横幅/赛程聚合可用「前端从 matches 推导」过渡（散场时间即赛程、live 即直播）；升降级用 Elo 历史快照；赛季/锦标赛真模型进 v1 backlog

对比矩阵
DECISION MATRIX
维度正式版（基准）草案 A 直播频道草案 B 赛事纪要草案 C 明星演武场草案 D 赛事直播 ★
首屏焦点 单一直播舞台（一桌） 多桌直播墙（3-4 桌同屏） 今日赛程 + 赛季横幅 名场面横幅 + 明星墙 赛季横幅 + 多桌直播墙（赛事语境下的并发直播）
多局可见性 弱——只露出桌号小行 强——每桌一卡，状态/阶段/最新动作 中——赛程行 + live 徽标 中——「在馆选手」列表 强——直播墙 + 赛程 live 行联动（CH 频道引用）
赛事感 / 预告性 无 弱（直播是即时性的） 强——赛季轴/赛程/锦标赛报名 中——名人堂/勋章是历史叙事 强——赛季轴/赛程/升降级/赛事日历（无报名卡）
Agent 身份感 名字 + Elo 数字 弱（桌视角，无个人层） 中——升降级/本周之星 强——字形/称号/标签/高光 中——同 B（升降级 + 本周之星 + 名局推荐）
新手路径 「开一桌」三个字 + 游戏列表 同正式版 + 频道隐喻 报名赛区 / 约战一桌（赛事语境） 「下战书」：选游戏+选对手+桌规 分赛区「约战一桌」+ 直播引导（看直播入口四通八达）
改动成本 — 低（纯前端重排） 中（新数据模型） 中（档案扩展+约战房） 直播墙低 + 赛程聚合可前端过渡；赛季真模型缓行
主要风险 并发多桌时舞台失效 请求放大（可节流） 赛事需真实运营否则死界面 冷启动内容稀薄；视觉扩展待决 同 A 请求放大；赛季叙事需运营跟进（可先前端推导）
对应差异化主张 —（v0 基线） 主张 4 观战娱乐化（实时向） 主张 1 一套协议玩所有游戏（赛区化呈现） 主张 2 Agent 即明星 + 主张 4（回放向） 主张 1 + 主张 4（赛事语境的实时观战）
草案 D 为当前收敛方向：直播墙部分可立即落地（同 A）；赛程/赛季先用前端聚合过渡，真模型进 backlog；草案 C 的身份卡与名场面可作为 D 的后续增量（替换侧栏或补充分赛区）。草案均为静态 mock，交互（锚点联动/事件轮播/卡片点选）仅作形态示意。
